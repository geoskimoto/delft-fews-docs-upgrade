## Minimal example

```xml title="Config/RegionConfigFiles/Parameters 1.00 default.xml"
<?xml version="1.0" encoding="UTF-8"?>
<parameters xmlns="http://www.wldelft.nl/fews" version="1.0">
  <parameterGroups>
    <parameterGroup id="Q">
      <parameterType>instantaneous</parameterType>
      <unit>m3/s</unit>
      <valueResolution>0.001</valueResolution>
      <usesDatum>false</usesDatum>
      <parameter id="Q.obs">
        <shortName>Q.obs</shortName>
        <description>Observed discharge</description>
      </parameter>
    </parameterGroup>
  </parameterGroups>
</parameters>
```

<Aside type="tip">
The `parameterGroup` carries the shared `parameterType`/`unit`/`valueResolution`;
the `parameter` inside is the id you reference elsewhere. See the [task
guide](/tasks/parameters/#anatomy-groups-vs-parameters) for why the split matters
and how `parameterType` affects aggregation.
</Aside>

## Gotchas

The consequential ones are covered in the task guide: [wrong `parameterType`
silently corrupts aggregation](/tasks/parameters/#gotchas), unit mismatches on
import, and confusing the **group** id with the **parameter** id. The
version-suffix trap applies here too — see [how FEWS finds a
file](/concepts/config-directory/#how-fews-finds-a-file).
