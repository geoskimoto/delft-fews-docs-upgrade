This page is the generated field list for the **temporal reshaping**
transformation functions — the families that change a series' time step or
time alignment without changing what it physically represents: running
totals, resampling to a coarser or finer time step, shifting in time, rate of
change, and bulk copying to a new module instance. Part of the
[transformation function catalogue](/reference/transformationbasics/#function-categories);
see that page for the shared `<transformationModule>`/`<transformation>`
mechanics these all sit inside.

## At a glance

<div class="field-list">

**Covers**

## Gotchas

- **`accumulation` vs `aggregation`** are easy to conflate: `accumulation`
  produces a **running/cumulative** curve at the *same* time step as the
  input (each output value is the running total so far); `aggregation`
  changes the time step itself (e.g. hourly sums rolled up into daily
  totals via `accumulative`). Reach for `aggregation` when you actually want
  fewer, coarser output values.
- **`disaggregation` needs a reference for shape**, not just a target time
  step — `accumulativeReferencePattern`, `weights`, and friends each define
  *how* to spread one coarse value across finer time steps; picking the wrong
  variant silently produces a flat (or badly shaped) disaggregation rather
  than an error.
- **`timeShift constant` only shifts, it doesn't extrapolate** — per its own
  schema annotation, it produces output only for the overlap between the
  shifted input and the output series' own time span. Don't expect it to
  invent values beyond the input's range.
- **`copy newModuleInstance`** (since 2025.02) is for bulk-copying *many*
  matching series at once via a filter (`inputTimeSeries`), not a single
  series — if you only need one series under a new module instance, a
  `variable`/`outputVariable` rename elsewhere is simpler.
