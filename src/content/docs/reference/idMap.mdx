## Minimal example

```xml title="Config/IdMapFiles/IdImportObservations 1.00 default.xml"
<?xml version="1.0" encoding="UTF-8"?>
<idMap xmlns="http://www.wldelft.nl/fews" version="1.1">
  <map internalLocation="RiverGauge_01" internalParameter="Q.obs"
       externalLocation="GAUGE-A"        externalParameter="discharge"/>
</idMap>
```

<Aside type="caution">
The moment you map even one location explicitly, the map acts as a **filter** —
unmatched series are silently dropped. This is the single biggest source of
"missing data." See [the task
guide](/tasks/id-mapping/#the-behavior-that-trips-everyone-up-the-map-is-also-a-filter)
and use `enableOneToOneMapping` for pass-through.
</Aside>

## Field reference

Note the shape below: `<map>`, `<parameter>`, `<location>`, and friends carry
their content in **attributes** (e.g. `internalLocation`, `externalParameter`),
so each links to a table of *attributes* rather than child elements. The
top-level `enableOneToOneMapping` / `enableCaseInsensitivity` /
`ignoreExternalQualifiersWhenMappingToInternal` are empty-element flags.

## Gotchas

Covered in depth in the task guide: [silent filtering](/tasks/id-mapping/#gotchas),
exact-match by default (case and punctuation), the bidirectional nature (the same
map drives export), and the compact cross-product. Version-suffix trap applies —
see [how FEWS finds a file](/concepts/config-directory/#how-fews-finds-a-file).
