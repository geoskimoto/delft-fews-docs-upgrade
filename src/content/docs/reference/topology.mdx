This page is the generated field list for `Topology.xml` — the tree a
forecaster actually clicks through in the Explorer / Interactive Forecast
Display / Web OC. Every other piece of region config (workflows, filters,
display groups, locations, thresholds) gets wired together here into
something a person can select and run.

## At a glance

<div class="field-list">

## Minimal example

```xml title="Config/RegionConfigFiles/Topology.xml"
<?xml version="1.0" encoding="UTF-8"?>
<topology xmlns="http://www.wldelft.nl/fews">
  <nodes id="RiverBasin" name="River Basin">
    <node id="Gauge01" name="Gauge 01">
      <workflowId>ForecastRiver</workflowId>
      <filterId>PublicObserved</filterId>
      <mainPanel>time series dialog</mainPanel>
    </node>
  </nodes>
</topology>
```

<Aside type="tip">
`<nodes>` nests recursively: a `<nodes id="...">` group contains a **repeated
choice** of leaf `<node>` entries, nested `<nodes>` sub-groups, or a
`<groupId>` that injects a group defined in a separate `TopologyGroups
*.xml` file (root element `<topologyGroup>`, same schema family). The
top-level `<topology>` root has the same choice — split a large tree across
files by mixing `<groupId>` references with inline `<nodes>` blocks. The field
reference below flattens this into a single field list; the choice/repeat
structure isn't visible there.
</Aside>

## Field reference

<Aside type="note">
This is the largest reference page in the guide — `<node>` alone carries

`filterId`/`locationId`, and one of the display-selection fields
(`mainPanel`, `displayConfigFileName`, or `explorerTaskName` — these three are
alternatives, not a set to combine).
</Aside>

## Gotchas

- **Display selection is a choice, not a set.** A node picks its main display
  via exactly one of `mainPanel` (built-in panel by name), a
  `displayConfigFileName`/`panelId`/`tabId`-style reference (config-file-driven
  display), or `explorerTaskName` (since 2021.02) — not several at once.
- **`groupId` only works if something defines that group.** It references the
  `id` attribute on a `<group>` in a separate `TopologyGroups *.xml` file
  (root `<topologyGroup>`) — a dangling `groupId` with no matching group is a
  silent-looking config error, not a crash.
- A parent node's workflow only runs when the tree is run **at the server**;
  running a parent node locally instead runs its children's workflows. See
  `localRun` and the run-button behavior in the schema docs for `node`.
