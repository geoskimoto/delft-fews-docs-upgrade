This page is the generated field list for the **data quality, selection &
control flow** transformation functions — smoothing/filtering a series,
tidal review, picking specific values out of a series (peaks, lows, extremes,
a time slice), summarizing discrete events, resampling at fixed points,
combining multiple sources into one series, branching on a condition, and
correcting values against a reference. Part of the [transformation function
catalogue](/reference/transformationbasics/#function-categories); see that
page for the shared `<transformationModule>`/`<transformation>` mechanics
these all sit inside.

## At a glance

<div class="field-list">

**Covers**

**Used inside**
: A `<transformation>`, `<periodTransformation>`, or `<rangeTransformation>`
in a [`transformationModule`](/reference/transformationbasics/) file.

## Gotchas

- **`merge simple`'s priority order is the `inputVariable` *document
  order*** — the first one wins wherever it has data; later ones only fill
  gaps. `reverseOrderInputTimeSeries` (in the required `coefficientSet`)
  flips that, and `reverseOrderAttributeId` can flip it per-location from a
  location attribute. There's no separate "priority" field to set — reorder
  the XML.
- **`merge simple` requires a `coefficientSet` even with nothing to
  configure** — the schema still requires at least one (with just
  `reverseOrderInputTimeSeries` set) even when you don't need
  range-dependent behavior. Leaving it out is a config error, not a
  default-everything shortcut.
- **`merge toggle` vs. `merge gap`**: both replace the primary series with
  the next input once a gap exceeds `maxGapLength`, but `toggle` *stays* on
  the replacement once switched (until it toggles back), while `gap` only
  substitutes for the duration of the gap itself. Picking the wrong one
  either produces an unwanted permanent source-switch or an unwanted
  reversion mid-event.
- **`selection` has near-identical `*Peaks`/`*Lows` pairs** (`peaks` vs.
  `independentLows`, `lows` vs. `independentPeaks`, etc.) — the
  "independent" variants find peaks/lows without requiring a full
  rise-then-fall cycle between them, which matters for noisy or
  closely-spaced series. Check the schema annotation for the specific
  variant before assuming it behaves like the plain one.
- **`adjust` corrects a computed series against an observed one** (e.g.
  adjust a modeled discharge to match the latest observed gauge reading) —
  it's not a general-purpose value editor; it needs both a computed input
  and a reference observed series configured.
