This page is the generated field list for the **hydrology & physical
process** transformation functions — stage/discharge conversion, rainfall and
soil moisture processing, longitudinal profiles, wave spectra, and
structure-based discharge calculations (weirs, pumps). The function
categories most specific to river/reservoir forecasting live here. Part of
the [transformation function
catalogue](/reference/transformationbasics/#function-categories); see that
page for the shared `<transformationModule>`/`<transformation>` mechanics
these all sit inside.

## At a glance

<div class="field-list">

**Covers**
: `stageDischarge` / `dischargeStage` (convert water level ↔ flow, via table,
power equation, merged rating curves, or a [rating
curve](/reference/ratingcurves/) file reference), `precipitation` (tipping
bucket → equidistant series, de-accumulation), `moisture` (optical depth,
soil moisture — grid series only), `profile` (longitudinal profile ↔ time
series), `wave` (generate 1D/2D wave spectra), `structure` (discharge through
a configured weir or pump — Crump weir, flat-V weir, general weir, four pump
variants).

**Used inside**
: A `<transformation>`, `<periodTransformation>`, or `<rangeTransformation>`
in a [`transformationModule`](/reference/transformationbasics/) file.

**Related**
: [Rating curves file](/reference/ratingcurves/) (the `ratingCurve` variant
references it by location) · [Structures file](/reference/structures/) (a
separate, static catalog of pump/weir capacity — not the same mechanism as
the `structure` transformation here).

</div>

## Gotchas

- **Two unrelated ways to get a rating curve into a transformation.** The
  `ratingCurve` variant of `stageDischarge`/`dischargeStage` looks up a curve
  from the standalone [Rating curves file](/reference/ratingcurves/) by
  `locationId` (+ optional `qualifierId`). The `table`/`power`/
  `mergedRatingCurves` variants instead take an inline or file-referenced
  `coefficientSet` (`coefficientSetId`/`coefficientSetFile`, from a
  `Config/CoefficientSetsFiles/transformationCoefficientSets` file — a
  different, not-yet-documented file family). Don't mix the two up: a
  `coefficientSetId` typo won't fall back to `RatingCurves.xml`.
- **`stageDischarge` and `dischargeStage` are mirror images**, not the same
  function with a flag — pick the one that names your actual conversion
  direction; each has its own `table`/`power`/`ratingCurve`/
  `mergedRatingCurves` variants.
- **`interpolationType: logarithmic`** on a `table` coefficientSet matters
  for discharge behavior near the low end of a rating — log interpolation
  avoids the unrealistic straight-line discharge a linear table can produce
  just above zero flow. Worth checking against gauged low-flow data if you
  see odd values there.
- **`structure` functions need the *matching* `coefficientSet` shape for
  their variant** — e.g. `generalWeirFixedHeight`'s height lives in the
  coefficient set, `generalWeirVariableHeight`'s comes from an input
  variable instead. Swapping variants without also updating the
  coefficientSet shape is a common source of a config that loads but
  computes nonsense.
- **`moisture` functions are grid-only** — `opticalDepth` and `soilMoisture`
  both require grid time series input; pointing them at a scalar series is a
  config error, not a silent no-op.
