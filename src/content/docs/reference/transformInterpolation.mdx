This page is the generated field list for the **interpolation & spatial**
transformation functions — filling gaps along the time axis
(`interpolationSerial`), moving values across locations or onto a grid
(`interpolationSpatial`), elevation-based adjustments (`altitude`), vector
rotation between coordinate systems (`rotation`), and computing a value from
location attributes (`multipleLocationAttributes`). Part of the
[transformation function catalogue](/reference/transformationbasics/#function-categories);
see that page for the shared `<transformationModule>`/`<transformation>`
mechanics these all sit inside.

## Gotchas

- **`interpolationSerial` fills gaps *within* one series** (time axis only);
  **`interpolationSpatial` moves values *across* locations or to/from a grid**
  (space axis) — they're not interchangeable despite the similar names. Use
  serial to patch a gauge record, spatial to turn point rainfall into a
  gridded field (or vice versa).
- **`maxGapLength` bounds how large a gap `interpolationSerial` methods will
  bridge** (in time steps) — omit it and an arbitrarily long stretch of
  missing data gets filled, rarely what you want. Same caution as on
  [interpolation sets](/reference/interpolationsets/) (the older, largely
  superseded file this function family effectively replaces).
- **Most `interpolationSpatial` methods need `searchRadius`/`numberOfPoints`
  tuned to your station density** — `inverseDistance` and `kriging` default
  to unbounded search radius and 8 points; a sparse network with far-apart
  stations may need a larger `searchRadius` or the result silently leans on
  distant, less-representative stations.
- **`altitude elevationLapse` needs a `coefficientSet`**, referenced either
  inline (`coefficientSet`) or from a separate file
  (`coefficientSetId`/`coefficientSetFile`, in `Config/CoefficientSetsFiles/`)
  — the lapse rate isn't a single number on the function itself.
- **`rotation`'s one method is narrowly scoped**: it rotates u/v vector
  *components* from a rotated-pole grid geometry to WGS 1984 — it doesn't
  reproject scalar grids. For scalar reprojection, look at `interpolationSpatial`
  methods instead (e.g. `bilinear`).
