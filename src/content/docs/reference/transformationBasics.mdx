This page is the generated field list for the **shared mechanics** of a
`transformationModule` file — everything about `<transformation>` that's the
same no matter which function it runs. The function catalogue itself (43
categories, from `accumulation` to `wave`) is split across separate pages
listed in [Function categories](#function-categories) below, because
together they're too large for one page (~400 types, ~3000 fields — see the
[Transformations task guide](/tasks/transformations/) for why).

## At a glance

<div class="field-list">

**Purpose**
: Runs one or more `<transformation>` steps in order, each reading an input
series and writing an output series through a chosen function.

**Folder**
: `Config/ModuleConfigFiles/`

**Root element**
: `<transformationModule>` (`version="1.0"`, required)

**Concept**
: [Transformations](/tasks/transformations/) task guide covers the
input→function→output pattern and a worked gap-filling example in full.

</div>

## Minimal example

```xml title="Config/ModuleConfigFiles/PreProcessObservations 1.00 default.xml"
<?xml version="1.0" encoding="UTF-8"?>
<transformationModule xmlns="http://www.wldelft.nl/fews" version="1.0">
  <transformation id="AggregateToDaily">
    <aggregation>
      <accumulative>
        <inputVariable>
          <timeSeriesSet>
            <moduleInstanceId>ImportObservations</moduleInstanceId>
            <valueType>scalar</valueType>
            <parameterId>P.obs</parameterId>
            <locationId>RainGauge_01</locationId>
            <timeSeriesType>external historical</timeSeriesType>
            <timeStep unit="hour" multiplier="1"/>
            <readWriteMode>read only</readWriteMode>
          </timeSeriesSet>
        </inputVariable>
        <outputVariable>
          <timeSeriesSet>
            <moduleInstanceId>PreProcessObservations</moduleInstanceId>
            <valueType>scalar</valueType>
            <parameterId>P.obs</parameterId>
            <locationId>RainGauge_01</locationId>
            <timeSeriesType>simulated historical</timeSeriesType>
            <timeStep unit="day" multiplier="1"/>
            <readWriteMode>add originals</readWriteMode>
          </timeSeriesSet>
        </outputVariable>
      </accumulative>
    </aggregation>
  </transformation>
</transformationModule>
```

This picks the `aggregation` family and its `accumulative` variant — see
[Temporal reshaping](/reference/transformtemporal/) for that family's own
field tables.

## Gotchas

- **`rangeTransformation` and `periodTransformation` wrap the same 43-way
  choice**, not a different one — a `<transformation>` picks a function
  directly, *or* wraps a series of `<rangeTransformation>`/
  `<periodTransformation>` blocks, each of which independently picks from the
  same function catalogue for its range/period. You can't currently nest a
  period-dependent choice inside a range-dependent one (or vice versa) in one
  step.
- **`<variable>` at the module root is optional** — most transformations just
  embed a `<timeSeriesSet>` directly in `inputVariable`/`outputVariable`
  instead. Declare a reusable `<variable>` only when several transformations
  need to reference the same series by `variableId`.
